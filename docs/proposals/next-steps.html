Next steps for HITLP

Status: proposed · Ticket #10

The question

Spec, diagrams, SDKs and demos of HITLP (human-in-the-loop-protocol) have landed. Everything is client side: no HITLP server, no real MCP transport, no conformance check. What next, in what order?

The proposal

Build the server side and the proof of conformance: MCP transport adapters, a reference server, a conformance suite, demos on the real server, then publish the SDKs.

Alternatives

Conformance suite onlyNoLowNothing to run the suite against

Open questions

  1. Reference server in this repo (assumed, under server/) or elsewhere?
  2. Server language? Assumed TypeScript.
  3. Durable store? Assumed SQLite, swappable.
  4. When does the spec leave draft, and may the SDKs be published before then?
  5. Which reserved primitive (Do, Inform, Escalate), if any, after step 5?

Implementation outline

  1. TypeScript MCP TaskTransport adapter.
  2. Python MCP TaskTransport adapter.
  3. Server skeleton: tools, durable store, R1, R4, R5.
  4. Server TTL, default action, caps (R2, R6).
  5. Server hosted decision page (§7.6, R7).
  6. Conformance suite, in CI against the server.
  7. Demos use the server.
  8. Publish to npm and PyPI, gated on question 4.
